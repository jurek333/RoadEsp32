# Code review: RoadEsp32 firmware (2026-10-31)

Scope: `src/` and `include/` C++ firmware. KiCad files, `lib/jsmn`, `res/` and Python scripts excluded. Read-only review by four parallel slices, then spot checks. Parts of the subagent output were truncated in the session, so this report lists only findings I can cite; items marked [INFERENCE] were not confirmed by running code.

## High

1. **Unsynchronized GPS shared state.** `src/sensors.cpp` writes `GpsSharedData` and `batteryLvl` without a lock. `Navigate::SetDestination` (UI task, `src/screens/navigate.cpp:52`) can interleave with `Sensors::ReadPositionInLoop` (sensor task, `sensors.cpp:69`). Readers may see a new destination with a stale distance or a torn lat/lon pair. *Fixed:* `SharedData::GpsLock` RAII guard around each group update. Readers in `gps.cpp` and `navigate.cpp` still need to copy under the lock; not verified on device.

2. **SD handle `0xFF` is not checked.** `src/modules/sdcard.cpp:87-102` returns `0xFF` from `OpenFile` on failure. `Write`, `Reset`, `CloseFile` and `Read` do not check it. `SmallBuffer::Get`/`Release` index `_buffor[hdr]` without bounds checks, and the buffer has 4 entries. `CloseFile(0xFF)` therefore writes `_buffor[255]` and `_occupied[255]`, corrupting adjacent `SdCard` members. Fix: bounds-assert in `SmallBuffer` and early-return on `FileHandlerExtnsions::IsEmpty(h)` in the `SdCard` methods.

3. **Route file handle leak.** `src/routeEsp32.cpp:48-51`: if `StartReading()` fails after a successful open (e.g. no `road/directions`), `CloseRoute()` never runs. The `new RouteReader` (`:56`) and the SD handle leak. `_files` has 4 slots (`sdcard.hpp:53`), so after four bad routes `OpenFile` returns `0xFF` until reboot. Fix: close, delete and clear the handle inside `ReadFile` on failure.

4. **JSON parser hangs at EOF.** `include/parser/jsonParser.hpp:51-52` (`ReadField`) and `:112-115` (`JumpOverCurrentState`) loop without checking for `'\0'`. `ReadNextChar` (`:164-171`) returns `'\0'` with `Unchanged` forever at EOF, so a truncated file or a missing value hangs the task. `GoToNext` (`:99-100`) already handles this. *Fixed in this session.*

5. **Frame clip comparison typo.** `include/data/images/images.hpp:73-74` compares `dy` against `innerDimmention` where it needs `outterDimmention`. The `DrawOptimizationType::Frame` path clips wrongly. No caller uses `frame` today, so the effect is latent. *Fixed in this session.*

6. **Low-battery text never redraws.** `src/screens/navigate.cpp:69-86` (`ShowBattery`): the redraw fires only on a change of at least 6 px in the bar length, which is clamped at 30 for `b<=10`. The `<=10%` text does not appear when dropping from 12% to 10%, and the displayed percentage goes stale. *Fixed in this session* by tracking `LastBattPct`.

7. **Extended glyphs never match.** `include/fonts/fonts.hpp:17-54` switches on a `char` with `0x80-0xFF` case labels. On a signed `char` (Xtensa GCC [INFERENCE]) those labels never match. *Fixed in this session* with `static_cast<unsigned char>`.

8. **Init errors and shutdown.** `src/routeEsp32.cpp`: init failures can leave the device stuck on the logo or panic (e.g. SD removed). `sensors.cpp`/`i2cPort.cpp`: all I2C calls use `ESP_ERROR_CHECK`, including `ReadDevice` every 100 ms, so a transient I2C error resets the chip. Replace with error returns for the polled read path.

## Medium

9. **`SmallBuffer` loop bounds.** `include/common/smallBuffer.hpp:23,45,58`: loops never terminate if `L > 255` with `uint8_t` `H`. Add `static_assert(L < max(H))`.

10. **JSON escapes kept raw.** `parserStateMachine.hpp:86-99`: `\"` stays `\"` and `\u00ca` stays literal. Decode them or document the behavior.

11. **Keyboard debounce.** `src/modules/kbrd.cpp`: the driver does not debounce. Debounce lives only in `KeysState` (`BothBtnThresholdCycles=5`). [INFERENCE] Acceptable if intended.

12. **Uninitialized handle.** `include/modules/powerMonitor.hpp`: `_adcHandle` is uninitialized before `Init`, so `Dispose` on an uninitialized handle is undefined behavior. Low severity.

13. **Unused handle.** `src/routeEsp32.cpp:32`: the `menu` handle is created and never used.

14. **Partial verification.** `threadSecureKeyboard.hpp` lock timeouts and `KeysState` counter logic were only partly read.
