# Code review: RoadEsp32 firmware (2026-10-31)

Scope: `src/` and `include/` C++ firmware. KiCad files, `lib/jsmn`, `res/` and Python scripts excluded. Read-only review by four parallel slices, then spot checks. Parts of the subagent output were truncated in the session, so this report lists only findings I can cite; items marked [INFERENCE] were not confirmed by running code.

## High

1. **Unsynchronized GPS shared state.** `src/sensors.cpp` writes `GpsSharedData` and `batteryLvl` without a lock. *Fixed:* `gps.cpp`, `navigate.cpp` and `navigate.hpp` readers now copy under `SharedData::GpsLock`. Compiles; not verified on device.

2. **SD handle `0xFF` is not checked.** `SdCard` methods already check `FileHandlerExtnsions::IsEmpty` before indexing `_files`. `SmallBuffer` bounds are covered by finding 9. No change needed.

3. **Route file handle leak.** `src/routeEsp32.cpp` / `navigate.hpp` `ReadFile` already calls `CloseRoute()` when `StartReading()` fails, closing the handle and deleting the reader. No change needed.

4. **JSON parser hangs at EOF.** `include/parser/jsonParser.hpp:51-52` (`ReadField`) and `:112-115` (`JumpOverCurrentState`) loop without checking for `'\0'`. `ReadNextChar` (`:164-171`) returns `'\0'` with `Unchanged` forever at EOF, so a truncated file or a missing value hangs the task. `GoToNext` (`:99-100`) already handles this. *Fixed in this session.*

5. **Frame clip comparison.** `include/data/images/images.hpp:73-74` already uses `dx < outter && dy < outter` in the current tree, so the `dy > outter` typo from the subagent report is not present. The `frame` kind has no users. No change.

6. **Low-battery text never redraws.** `src/screens/navigate.cpp` `ShowBattery` already tracks `LastBattPct`, so the redraw issue is handled. No change this session.

7. **Extended glyphs never match.** `include/fonts/fonts.hpp:17` already casts to `unsigned char` before the switch, so `0x80-0xFF` labels match. No change this session.

8. **Init errors and shutdown.** `src/routeEsp32.cpp`: init failures can leave the device stuck on the logo or panic (e.g. SD removed). `sensors.cpp`/`i2cPort.cpp`: all I2C calls use `ESP_ERROR_CHECK`, including `ReadDevice` every 100 ms, so a transient I2C error resets the chip. Replace with error returns for the polled read path.

## Medium

9. **`SmallBuffer` loop bounds.** `include/common/smallBuffer.hpp`: `static_assert(L < max(H))` added. *Fixed.*

10. **JSON escapes kept raw.** `parserStateMachine.hpp:86-99` leaves escapes raw; `ReadField` in `jsonParser.hpp` now decodes `\"`, `\\`, `\n`, `\t`, `\r`, `\b`, `\f`, `\uXXXX` (BMP only, to UTF-8; surrogate pairs not combined). *Fixed;* verified with a host harness.

11. **Keyboard debounce.** `src/modules/kbrd.cpp`: the driver does not debounce. Debounce lives only in `KeysState` (`BothBtnThresholdCycles=5`). [INFERENCE] Acceptable if intended.

12. **Uninitialized handle.** `include/modules/powerMonitor.hpp`: `_adcHandle` now defaults to `nullptr`, and `Dispose` is a no-op when it is null. *Fixed.*

13. **Unused handle.** `src/routeEsp32.cpp:32`: the `menu` variable was removed and `nullptr` passed to `xTaskCreatePinnedToCore`. *Fixed.*

14. **Partial verification.** `threadSecureKeyboard.hpp` lock timeouts and `KeysState` counter logic were only partly read.

## Low / cleanup

- `src/protocols/i2cPort.cpp:17`: `trans_queue_depth` set to `0` explicitly (was commented out; behavior unchanged). *Fixed.*
